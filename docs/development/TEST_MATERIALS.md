# 準備測試素材

你只要**放檔案，再告訴工作聊天一句希望測什麼**，不需要自己算雜湊或整理
技術清單。例如：「用這個走路動作，確認表情切換時角色動作不會中斷。」

## 檔案放這裡

本機收件資料夾：`D:/Projects/BCON26/motion_codedev/test_materials/inbox/`

- `motions/`：動作檔。
- `scenes/`：Blender 測試場景。
- `characters/`：測試角色與骨架。
- `references/`：圖片、影片或測試說明。

動作與場景建議用 `名稱_v001` 命名，例如 `walk_v001.bvh`、`stage_v001.blend`。
更新時留一份 `v002`，保留舊版本，讓已經開工的聊天繼續使用原來的測試基準。
若場景需要其他素材，把依賴檔案一起放好，或告訴聊天它們的位置。

這是本機資料夾，**放檔不會自動上傳 GitHub**。GitHub／雲端測試也不能直接
讀取你電腦上的檔案；需要材料的本機聊天會先核對檔案是否可讀。

## 工作聊天負責的事

在對應 Issue 或既有驗證紀錄中整理以下資料，不另開一套素材表：

- 來源／作者、授權與是否可分享；未確認分享範圍的材料保留本機。
- 檔案名稱與素材版本、SHA-256、大小；雜湊由技術角色計算。
- Blender 版本、Node addon ID／版本、測試的程式 commit。
- 動作 FPS、frame 區間、骨架／角色與 Action；不適用的欄位註明即可。
- 希望看到的結果、必要依賴與實際測試結果。

原檔唯讀使用。每個任務把所需版本複製到自己的工作區，在獨立 Blender
profile、場景複本及輸出目錄測試，不回存收件原檔或另一聊天的複本。

大型、私人或尚未確認可分享的材料不自動提交 GitHub。技術角色只按最新
Issue scope 和測試用途，挑選必要的小型 fixture 納入版本控制。Node fixture
預定放 `tests/yugu_node_studio/fixtures/`，由導入／測試任務建立，目前尚不存在；不得把整個
收件資料夾、完整角色庫、測試輸出或生成 ZIP 加進程式歷史。

雲端需要材料時，另安排適合分享的版本與可存取位置，記錄版本及 SHA-256。
材料不可取得或依賴不完整時，明確記為「未執行／等待材料」，不能算測試通過。
